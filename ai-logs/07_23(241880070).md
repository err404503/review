中文翻译
Bloom Filters（布隆过滤器）
Bloom [Blo70] 提出的优雅数据结构自然支持动态插入，但其空间使用比信息论下界 nlog⁡(1/ϵ)  n \log(1/\epsilon)  nlog(1/ϵ) 比特大了 log⁡e≈1.44  \log e \approx 1.44  loge≈1.44 倍 [CFG+78]。
需要注意的是，Bloom 过滤器不支持删除操作，因为将任何比特位设为 0 都可能导致假阴性（false negative）。
使用计数型 Bloom 过滤器（counting Bloom filters）[FCA+00] 可以支持删除，但会使空间开销增加 Ω(log⁡log⁡n)  \Omega(\log \log n)  Ω(loglogn) 倍。删除的含义是：只要不尝试删除假阳性元素，数据结构就能正常工作，但本质上无法完全防止此类删除。Cohen 和 Matias [CM03] 提出了一种将空间额外开销降低到 O(n)  O(n)  O(n) 比特的方法，并将近似成员查询推广到了多重集（multiset）的近似重数（approximate multiplicity）。
基于字典的近似成员查询（Dictionary-based approximate membership）
早在 1978 年，Carter 等人 [CFG+78] 就提出了类似技术。他们观察到，维护多重集 h(S)  h(S)  h(S)（其中 h:[u]→[n/ϵ]  h: [u] \to [n/\epsilon]  h:[u]→[n/ϵ] 是通用哈希函数 [CW79]），如果能以接近信息论下界 log⁡(n/ϵ+nn)  \log \binom{n/\epsilon + n}{n}  log(nn/ϵ+n​) 比特的空间存储该集合，就能得到空间为 nlog⁡(1/ϵ)+O(n)  n \log(1/\epsilon) + O(n)  nlog(1/ϵ)+O(n) 比特的方案。若不需要删除，只需存储 distinct 的哈希值 h(S)  h(S)  h(S) 即可。该动态集合可以用 [ANS10] 中的方法以高概率 O(1)  O(1)  O(1) 时间操作实现紧凑存储。
动态多重集（从而支持删除）可以通过归约到标准成员查询问题 [PPR05] 来实现，但会带来期望摊销的更新时间界。
更实用的替代方案在 [BMP+06] 中被探讨。
在线与离线空间需求的分离（Separation of on-line and off-line space requirements）
Dietzfelbinger 和 Pagh [DP08] 展示了如何在 ϵ  \epsilon  ϵ 是 2 的整数幂时，通过查询时间 ω(log⁡(1/ϵ))  \omega(\log(1/\epsilon))  ω(log(1/ϵ)) 来逼近 nlog⁡(1/ϵ)  n \log(1/\epsilon)  nlog(1/ϵ) 空间下界（误差 o(n)  o(n)  o(n)）。Porat [Por09] 独立地以常数查询时间达到了相同结果。最近，Belazzougui 和 Venturini [BV13] 去除了对 ϵ  \epsilon  ϵ 的限制，同时保持常数查询时间。
Lovett 和 Porat [LP10] 证明，这些静态情况下的结果无法直接推广到允许动态更新的情形：需要 Ω(n/log⁡(1/ϵ))  \Omega(n / \log(1/\epsilon))  Ω(n/log(1/ϵ)) 比特的额外空间。该下界即使在插入序列结束前不进行任何查询也成立。换言之，对于以数据流形式给出的键集，要构造近似成员数据结构，仅使用接近静态大小下界的空间是不够的。
动态空间使用（Dynamic space usage）
当空间必须随当前集合大小动态变化时，对上界构造的要求更高。文献中能找到的针对该问题的技术 [ABP+07, HKL08, GWC+06, GWC+10, WJZ+11, WJZ+13] 都会导致查询时间 Ω(log⁡n)  \Omega(\log n)  Ω(logn) 或 Ω(log⁡(1/ϵ))  \Omega(\log(1/\epsilon))  Ω(log(1/ϵ))，以及空间额外开销 Ω(nlog⁡n)  \Omega(n \log n)  Ω(nlogn) 比特。这些数据结构的核心思想是维护一系列近似成员数据结构，并对所有结构进行查询。如果采用几何递增的容量，就会存在 Ω(log⁡n)  \Omega(\log n)  Ω(logn) 个这样的结构（当然，如果有初始容量 n0  n_0  n0​，数量会降到 O(log⁡(n/n0))  O(\log(n/n_0))  O(log(n/n0​))，这在实际中可能可接受，但不是渐近最优的）。
使用多个近似结构的后果是，对应的假阳性率 ϵ1,ϵ2,…  \epsilon_1, \epsilon_2, \dots  ϵ1​,ϵ2​,… 之和必须收敛到 ϵ  \epsilon  ϵ。例如在 [ABP+07] 中，建议让 ϵi  \epsilon_i  ϵi​ 随 i  i  i 几何递减，这会导致 ϵi=n−Ω(i)  \epsilon_i = n^{-\Omega(i)}  ϵi​=n−Ω(i)，从而空间使用达到 Ω(nlog⁡n)  \Omega(n \log n)  Ω(nlogn)。
动态完美哈希与检索（Dynamic perfect hashing and retrieval）
在静态情形下，一种近似成员查询的方法是存储一个完美哈希函数，将键单射映射到 {1,…,n}  \{1, \dots, n\}  {1,…,n}，然后在数组中为每个键存储 log⁡(1/ϵ)  \log(1/\epsilon)  log(1/ϵ) 比特的签名。更一般地，动态检索（retrieval）数据结构（如 [CKR+04] 中的 Bloomier 过滤器）可用于构造动态近似成员数据结构。
如 [MPP05] 所示，这两个问题在在线（on-line）设定下都需要 Θ(nlog⁡log⁡n)  \Theta(n \log \log n)  Θ(nloglogn) 比特的空间。然而，其上界具有固定的空间使用（常数因子内），因此无法实现我们本文得到的那种随集合大小渐进最优的空间消耗。
解读与分析
本节核心意义：
1.2 节系统梳理了与“未知大小集合的动态近似成员查询”相关的前人工作，明确了本文的创新位置：

已知最优：当集合大小 n  n  n 提前已知时，空间可达 Θ(nlog⁡(1/ϵ))  \Theta(n \log(1/\epsilon))  Θ(nlog(1/ϵ)) 比特（Bloom 过滤器及其改进）。
未知大小场景：现有方案要么空间浪费极大（Ω(nlog⁡n)  \Omega(n \log n)  Ω(nlogn)），要么查询时间较差，要么不支持完全动态操作。
本文首次从理论基础角度证明：未知大小时必须付出 Ω(nlog⁡log⁡n)  \Omega(n \log \log n)  Ω(nloglogn) 的额外空间代价，并给出了几乎紧致的构造。

关键技术路线对比：

Bloom 系列：简单实用，但空间有常数因子损失，且传统版不支持删除。
字典+哈希签名：理论上可达最优空间，但动态版本面临在线空间挑战。
多层/可扩展 Bloom：实际工程常用，但渐近不优（多层导致 log⁡n  \log n  logn 查询或 log⁡n  \log n  logn 空间因子）。
本文贡献：通过“压缩论证”给出下界，并用“几何增长 + 字典”与“单字典 + 签名扩展 + 去摊销”两种构造匹配下界，同时保持高效操作。

实际启示：

在大数据流场景（如网络监控、数据库缓存、分布式系统）中，集合大小往往无法提前预知。本文工作解释了为什么简单扩展 Bloom 过滤器会浪费空间，并为设计“空间自适应”的近似成员结构提供了理论指导。
后续实际实现仍需进一步优化隐藏常数和工程细节（论文 6 节也明确指出了这一点）。
